Molecule

Copy field

A value the person is meant to take away, with the button that takes it, in one row.

Anatomy

  • .wf-copythe row: the input takes the space, the button takes what it needs
  • .wf-copy .wf-inputthe value, read only, flexed to fill
  • .wf-btnthe outline button, because the copy is not the action the screen exists for

Variants and sizes

The empty cells, and why they are empty

No size axis. It is as wide as its container on every screen.

When to use it

The roster, where the operator takes the check-in link to paste into Slack, and the invite screens. Eleven screens. It is the moment the product leaves Brio and goes where the team already is.

The rule, and the anti rule

Do this. Keep the value visible and selectable. A person who does not trust a copy button will select the text by hand, and they should be able to.

Not this, use Field instead. Do not use it for a value nobody needs to take away. A value that is only read is text, and a value that is edited is a Field.

States

The states are the button's and are documented there. The row itself has none: the flex rule that makes the input fill the row is composition, and it lives in copy-field.css rather than in the input.

No snapshots here, and that is the rule rather than an omission. The unit of a snapshot is a difference, not an occurrence. This component answers every state exactly as Button does, so the answer is written in this line instead of proved again with pictures. A matrix with more snapshots than named differences is a list of occurrences, not documentation.
