Outcome badge

A round plate with one glyph in it, at the top of a screen that has one thing to say.

Anatomy

✓
!
  • .wf-badgethe plate: a 56px circle, the glyph centred at the largest type step
  • .wf-badge.okthe soft accent fill with primary ink on it
  • .wf-badge.warnno fill, the alert colour on the ink and on the border

Variants and sizes

Emphasis

Two values, and they are the two things an outcome screen can be: it happened, or it did not.

✓

ok
the check-in is done, the message was sent

!

warn
the link expired, the answer did not go through

Size

Set by the viewport, not by importance: under 520px the badge gives back twelve pixels so the action underneath it stays reachable without scrolling.

✓

default
56px, from 520px up

✓

small
44px, under 520px

When to use it

The top of an outcome screen in the employee flow: check-in done, link expired, already answered, could not send. It is the first thing the eye lands on and it says which of the two kinds of screen this is before a single word is read.

The rule, and the anti rule

Do this. One badge per screen, at the top, above the heading. The screen it stands on has exactly one thing to say.

Not this, use State block instead. Do not put a badge on a screen that continues. A screen with a next step and a state to report is a State block, which carries a title, a sentence and an action together.

States

No states: this component is not interactive. Not interactive: it reports, it does not respond. The responsive step below 520px is a size change and not a state, and it now lives in badge.css rather than in a :root override that used to resize the Icon slot along with it by accident.
