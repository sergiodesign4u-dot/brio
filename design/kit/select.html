Atom

Select

The input box with a chevron. A second component rather than a variant, because it has a zone the input does not.

Anatomy

  • select.wf-inputthe same box as the input, with the native arrow removed
  • background-imagethe chevron, a Solar glyph placed by the mask mechanism
  • padding-rightthe room the chevron needs, from --space-icon-inset

Variants and sizes

Content

One value. The product uses a select in exactly one place, the answer type of a check-in question.

one form
check in setup

The empty cells, and why they are empty

No emphasis axis and no size axis: a select is a field control and takes the geometry of the field it sits in.

When to use it

On check-in setup, where the operator chooses how a question is answered. It is in the system on one appearance under the form control exception, because a control that lives on a screen instead of in the system drifts with the next screen that needs it.

The rule, and the anti rule

Do this. Use it when the choice is one of a closed list and the list is longer than three. Two or three visible choices are Radio options, which show all the answers at once.

Not this, use Chip instead. Do not use a select to filter a list. The program library filters with Chips, which stay visible after they are chosen.

States

The chevron does not rotate on open: the native popup already tells the person it is open, and rotating it would be a second answer to the same question.

No snapshots here, and that is the rule rather than an omission. The unit of a snapshot is a difference, not an occurrence. This component answers every state exactly as Input does, so the answer is written in this line instead of proved again with pictures. A matrix with more snapshots than named differences is a list of occurrences, not documentation.
